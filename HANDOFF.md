## Хостинг
Текущий код рассчитан на один постоянный Node-процесс и диск: SQLite/WAL и локальные uploads. Предпочтителен уже оплаченный владельцем Node/Docker-хостинг с постоянным томом. Не утверждать, что Vercel заработает без адаптации: для обычного serverless-размещения потребуются внешняя БД, объектное хранилище и общее хранилище сессий/лимитов. Это отдельная миграция, тарифы надо проверить до подключения. Не подключать платные ресурсы без разрешения.
Постоянно хранить `/app/data` и `/app/assets/uploads`, задать `FASHION_ORIGIN` точным HTTPS origin, `PORT=3000`, `FASHION_DB=/app/data/fashion.sqlite`. `.env.example` — только документация, приложение не читает dotenv автоматически. Создать первого пользователя через `npm run user` в приватной консоли хостинга; пароля по умолчанию нет. Для неинтерактивной консоли использовать manage.mjs user со stdin через защищённый механизм хостинга. Проверить health `/api/health`, вход/выход, файлы и сохранность после рестарта.

## Проверки, которые ещё нельзя считать пройденными
В текущей среде ранее подтверждён listen EPERM. Docker daemon возвращает permission denied. Попытка открыть файловый прототип в Cloud Browser отклонена политикой URL (только http/https). Обходы ограничений не выполнялись. Поэтому реальный HTTP, браузерный путь, визуальный desktop/390px, Safari/iPhone, работоспособность языкового DOM-наблюдателя, сборка и запуск контейнера остаются открытыми. Автоматические Request/Response тесты не заменяют эти проверки.

После размещения на закрытом тестовом HTTPS-адресе:
1. Проверить главную/три мира, меню, desktop/390px/iPhone Safari, отсутствие горизонтального переполнения, фото/анимации/reduced-motion.
2. Все три языка, фильтры/избранное/недавние/образ/корзину, размеры/цвета/недоступность, увеличение/видео/Escape.
3. Вход/выход owner/editor, создание/правку товара/категории/подкатегории/бренда/фото/перевода/настроек, конфликт двух окон; закрытость supplier/cost/finance API.
4. Демо-корзину со смешанными сроками и промокодом → заказ → админка → резерв → передача → завершение → отчёт. Нажать повторно, обновить после сетевого сбоя. Открывать WhatsApp только с тестовым содержимым и разрешённым владельцем номером, не отправлять без явного поручения.
5. Конкурирующие резервы/отмену/товар в пути/приход/повторное списание/пригодный и повреждённый возврат. Обмен оформляется возвратом и новым заказом.
6. Закупку с 101 тетри логистики на 3 единицы, FIFO, расходы, долги/оплаты, фильтры отчёта, возврат в другом отчётном периоде.
7. Перезапуск и восстановление SQLite online backup вместе с uploads; не заменять открытую БД, не переносить старые WAL/SHM в восстановленный каталог.

## Осознанные границы версии
Нет онлайн-оплаты/платного WhatsApp API/Telegram-ботов/рассылок/кабинетов поставщиков. Обмен — возврат + новый заказ; частичный возврат в текущем UI не реализован (возврат всего заказа с единым признаком состояния). Есть общий образ через флаги look и отдельные редактируемые подборки товаров; вложенная иерархия коллекций не предусмотрена. Видео — HTTPS URL, не загрузка/перекодирование. Доставка без автоматического тарификатора; итог заказа исключает ещё не согласованную стоимость доставки. Промо применяется к целому заказу. Прикладные настройки редактируются, секреты — только приватной консолью/окружением. Сессии и лимиты в памяти одного процесса; несколько реплик требуют общей сессии/лимитов и другой архитектуры БД. Демоданные не являются реальными предложениями.
