# Этапы и критерии
Последнее поручение владельца расширило текущий запуск до оставшихся этапов и передачи исходников в GitHub. Прежнее ограничение одного этапа за запуск заменено этим прямым поручением. Работать поверх сохранённого кода, не начинать заново.

| Этап | Критерий | Статус |
|---|---|---|
| 1. Основа и вид | Запуск, три мира, desktop/mobile, адаптивное движение | Код есть; реальный HTTP и визуальная приёмка открыты |
| 2. Каталог/корзина | Выбор модели/варианта → заполненная корзина, фильтры/избранное/образы | Код и тесты есть; браузерная приёмка открыта |
| 3. БД/админка | Создание/изменение товара отражается в постоянном каталоге, коммерческие данные закрыты | Проверено интеграционно на SQLite/API; браузер открытый |
| 4. Заказы/WhatsApp | Снимки/номера/дубли/история, полное сообщение с источником | Код и автоматические проверки пройдены; реальный номер не задан, сообщения не отправлялись |
| 5. Склад/поставки | Резерв/отмена/однократное списание/возврат/приход, без отрицательных остатков | Проверено на тестовых операциях |
| 6. CRM/финансы | История/сегменты/затраты/FIFO/выручка/расходы/долги, точная сверка | Проверено на тестовых операциях |
| 7. Языки/продажи | RU/KA/HY, редактируемые переводы, рекомендации/промо/образы | Код и автоматические проверки; вычитка языков и браузер открыты |
| 8. Финальное тестирование/передача | Реальные браузеры, iPhone Safari, сеть/контейнер, backup/безопасность/финансы/языки; README и GitHub | 16 тестов прошли, handoff и Docker/CI подготовлены. ## Перенос хранения на Vercel + Supabase (план, не начат в коде)
Оценка 27.11.2026: 92 обращения к БД (`db.prepare`), 25 транзакций, синхронный API `node:sqlite` во всех модулях `backend/`. Сессии, лимиты входа и заказов в памяти процесса. Фото в `assets/uploads/` на диске. Это не точечная замена, а переписывание слоя данных.

Шаги, каждый с тестами и коммитом:
1. Слой доступа: async-интерфейс над БД (sqlite для локальных тестов, Postgres для Supabase), без изменения бизнес-правил.
2. Перенос схемы и транзакций (остатки, заказы, финансы, FIFO) с проверкой тех же 16 тестов на обеих БД.
3. Сессии и лимиты входа/заказов в БД вместо памяти процесса.
4. Фото в объектное хранилище (Vercel Blob): загрузка, ссылки, удаление; лимит размера тела запроса Vercel учесть.
5. Адаптация точки входа под serverless (Vercel Functions) и проверка HTTPS-адреса.
6. Резервное копирование: через Supabase, не через копирование файла.

Ключи Vercel и пароли БД не хранить в репозитории. Лицензия Vercel Hobby — только тестовый режим, без продаж.
