# FASHION — демонстрационный магазин одежды

Исходники: https://github.com/xugushik-source/fashion-store — публичный репозиторий по разрешению владельца, ветка `work/stage-1`. Это код приложения, не адрес работающего магазина.
Существующий проект продолжен до кода этапов 1–7: кинематографичная витрина, три направления, каталог/корзина, SQLite, защищённая админка, заказы/WhatsApp, склад, закупки/FIFO, CRM/финансы, RU/KA/HY, акции и редактируемые образы. Всё остаётся demo. Этап 8 закрыт только в части автоматических проверок: живой браузер/iPhone и контейнер не проверены из-за ограничений среды. Реальные продажи не включены. Точный статус — PROGRESS.md; передача — HANDOFF.md.

## Запуск
Node.js **24+**, встроенный `node:sqlite`; npm-зависимостей нет.
```
cd /workspace/fashion
npm run init
npm run user
npm start
```
`user` запрашивает имя, роль owner/editor и пароль от 12 символов со скрытым вводом. Пароля по умолчанию нет. Витрина http://localhost:3000, админка http://localhost:3000/admin, readiness `/api/health`. Это адреса локального запуска, не опубликованный сайт. Node-сервер не читает `.env` автоматически: задавайте переменные в окружении хостинга/контейнера.

`FASHION_ORIGIN` — точный внешний origin (по умолчанию http://localhost:3000), `FASHION_DB` — путь SQLite (по умолчанию data/fashion.sqlite относительно cwd), `PORT` — порт (3000). Для другого порта меняйте origin и PORT; для внешнего размещения HTTPS обязательно, Secure cookie включается по HTTPS origin. Dockerfile рассчитан на один процесс и два постоянных тома: `/app/data`, `/app/assets/uploads`. Сборка/запуск контейнера здесь не проверены: доступ к Docker daemon запрещён. Не переносите текущую локальную SQLite и файловые uploads в serverless Vercel без адаптации хранения/сессий. Подробности HANDOFF.md.

Смена пароля: `npm run user` с тем же именем; прежние сессии прекращаются при следующем запросе. Неинтерактивная альтернатива: `node manage.mjs user <username> <owner|editor>`, пароль передаётся только через stdin защищённым механизмом. Пароли/токены не помещать в аргументы, Git или переписку.

## Работа с демомагазином
- В админке создавать/редактировать товары, категории и подкатегории, бренд, название/описание/состав/таблицу размеров, цену в GEL, варианты, доступность, срок и фото (JPEG/PNG/WebP до 3 МБ). Опциональное видео — HTTPS URL. Скрытие через «Показывать на витрине». Данные сервером всегда маркируются demo. Первое фото — обложка, остальные увеличиваются из карточки.
- Начальные остатки задаются при создании нового варианта. Остаток существующего варианта изменять через Склад/Закупки. Нельзя удалять вариант с фактическим остатком или историей заказов; используйте статус недоступности. При конфликте двух окон обновить список и открыть карточку заново.
- Владелец видит поставщиков/контакты/условия, себестоимость и финансы. Редактору эти сведения не выдаются. Оба управляют каталогом, заказами и CRM; складские изменения и денежные операции доступны владельцу.
- Покупатель выбирает варианты, собирает образ, добавляет в избранное/корзину, фильтрует товары. Корзина/избранное/недавние — localStorage этого браузера, без синхронизации устройств. При запрете localStorage интерфейс работает в памяти и сообщает об ограничении.
- Заказ: только вымышленные контакты → получение/адрес/смешанные сроки → согласие на тестовую обработку → серверная проверка цены/наличия/промо → сохранение снимка и номера FS-… → сообщение/ссылка WhatsApp. Пустой номер магазина не подменяется вымышленным: заказ сохраняется, сообщение показывается, внешняя ссылка отключена. Адреса и контакты заказа не доступны публичным GET-маршрутам.
- Открыть WhatsApp не означает отправить или подтвердить продажу. Никаких Telegram-ботов, платного WhatsApp API или автоматических рассылок. Повторный запрос защищён ключом; браузер хранит ключ/хэш незавершённого запроса без сырых контактных данных. После успешного сохранения корзина очищается.
- Новый заказ → подтверждён (резерв) → ожидает поставку/готов → передан (списание) → завершён (выручка). Отмена до передачи освобождает резерв; возврат после передачи/завершения учитывает пригодность. Пригодный возврат возвращается в остаток и FIFO-оценку, повреждённый не предлагается снова. Обмен — возврат и новый заказ. Частичный возврат сейчас не предусмотрен.
- Склад разделяет факт, резерв, в пути, лимит под заказ. Поступление из пути и передача покупателю не допускают отрицательных значений. Журнал операций и повторные команды защищены ключами.
- Закупка создаёт приход и FIFO-лоты. Перевозка/таможня/прочее распределяются по единицам в целых тетри с сохранением всей суммы. Фактическая себестоимость фиксируется при передаче. Для импортного товара вводить подтверждённые расходы и сроки вручную.
- Финансы учитывают завершения/возвраты по датам событий, FIFO-себестоимость, расходы и долги/оплаты поставщикам. Предоплата поставщику даёт отрицательный баланс. Долг относится к базовой закупке, логистика включается в оценку товара. Фильтры товаров/категорий/поставщиков не распределяют общие операционные расходы: отчёт это обозначает. Управленческий расчёт не заменяет налоговый учёт.
- CRM собирает историю, завершённую сумму, повторные покупки, размеры/категории/сегменты; заметки/предпочтения редактируются отдельно, приватно. Рассылок нет.
- Настройки: название/логотип/источник/WhatsApp/сегменты/сведения продавца/условия и обработка данных. Логотип — путь существующей загруженной картинки. Переводы: точная русская строка → грузинский/армянский. Для новых товаров и условий заполнить переводы до публикации. Основной публичный UI и сообщения переведены, требуется вычитка KA/HY носителями.
- Промокоды: включение, процент 0–90, даты UTC; скидка фиксируется в заказе с распределением по строкам в тетри. Коллекции/образы — именованные наборы товаров с включением/выключением, видны в блоке образов. Непродаваемая скрытая позиция исключает набор из публичного списка.

## Проверки и ограничения среды
```
npm run check
```
Проверяется синтаксис всех JS/MJS, затем 16 тестов: каталог/фото/экранирование, фильтры/корзина, DOM-заглушки обработчиков, SQLite/API/auth/owner/editor/CSRF/приватность/конфликт/backup, заказ/снимок/идемпотентность, резерв/отмена/повторное списание/возврат/поставка, точная FIFO-себестоимость/финансы/CRM, KA/HY статического текста и заказа, промо/редактируемые коллекции, сквозной серверный сценарий от заказа до финансов и отзыва сессии после смены пароля.

Это не тест реального HTTP-порта или браузера. Ранее подтверждён `listen EPERM`. Файловый URL в Cloud Browser запрещён политикой (http/https only), обход не выполнялся. Docker daemon — permission denied. Поэтому desktop/mobile/iPhone Safari, визуальная скорость, настоящий ввод форм/переключение языка, сборка контейнера и полный сетевой запуск остаются обязательной приёмкой после размещения. GitHub Actions workflow добавлен только для ручного запуска, не запускался, расходы не создавались.

## Бэкапы
```
npm run backup -- /абсолютный/путь/backup.sqlite
```
SQLite online backup, а не копирование открытого файла. Сохранять БД и **весь assets/uploads/** вместе вне публичного каталога/репозитория, с доступом только владельца. Восстановление: остановить сервер, сохранить текущие данные, восстановить БД в новый путь, указать FASHION_DB, восстановить фото, запустить/проверить. Не переносить старые WAL/SHM поверх восстановленной БД. Чтение online backup проверено тестом; внешнее расписание/хранилище не подключены.

## Файлы
`app.js`, `shop-core.js`, `shop.js`, `checkout.js`, `recent.js`, `collections.js`, `content.js`, `i18n.js`, `translation-core.js`, `locales.json` — витрина. `loader.js` загружает каталог/настройки API перед приложением; при ошибке не подменяет БД зашитыми товарами. Файловое открытие — только ограниченная автономная демонстрация, полноценный магазин требует HTTP. `admin.*`, `operations.js` — админка. `backend/` — БД/валидация/вход/API/заказы/склад/FIFO/CRM/промо. `server.mjs` — HTTP, `manage.mjs` — init/stdin-user/backup, `create-user.mjs` — скрытый ввод, `scripts/check.mjs`, `tests/` — проверки. Рабочая БД и uploads исключены из Git. Seed не перезаписывает пользовательский каталог; одна безопасная миграция обновляет исходную неиспользованную демокарточку кардигана на обувь.
