# FASHION — локальный магазин, этапы 1–3
Главная, три визуальных направления, демонстрационный каталог, варианты, фильтры, избранное, образы, локальная корзина; постоянная SQLite-база и защищённая админка каталога. Все карточки, цены, составы и остатки тестовые. Продажи не ведутся. Заказы/WhatsApp, реальные резервы, CRM и финансы — будущие этапы.

## Запуск
Требуется Node.js **24+** со встроенным `node:sqlite`. Устанавливать зависимости не нужно.
```
cd /workspace/fashion
npm run init
npm run user
npm start
```
`user` интерактивно запросит имя, роль owner/editor и пароль от 12 символов со скрытым вводом. Пароля по умолчанию нет. Для смены пароля повторите команду с тем же именем и перезапустите сервер (сбросит сессии). Витрина: http://localhost:3000; админка: http://localhost:3000/admin.

Для автоматизированного локального создания пользователя: `node manage.mjs user <имя> <owner|editor>`, пароль только через stdin, не аргументом командной строки. Не сохраняйте пароли в коде, Git, журнале или истории команд.
`FASHION_DB` задаёт абсолютный путь БД (по умолчанию `data/fashion.sqlite` относительно cwd); `PORT` — порт; `FASHION_ORIGIN` — точный внешний origin (по умолчанию `http://localhost:3000`). При другом порте/домене меняйте и origin. Для будущего размещения необходим HTTPS и `FASHION_ORIGIN=https://...`: cookie получит Secure. Внешнюю публикацию не выполнять без разрешения.

В этой среде ранее зарегистрирован `listen EPERM` на 3000. Рабочий HTTP URL и браузерная приёмка не подтверждены. В этой сессии сервер не перезапускался в обход ограничения. API проверен через Web Request/Response без открытия порта, с реальной временной SQLite-базой.

## Администрирование
1. Войти. Выбрать существующую карточку или «Новый товар».
2. Указать название, артикул, категорию/сегмент, цену в GEL, описание/состав. Все товары пока сохраняются с флагом demo.
3. Загрузить JPEG/PNG/WebP до 3 МБ, удалить лишние фото, добавить размеры/цвета, тестовый остаток, доступность и срок. Минимум одно фото и один вариант обязательны. Первое фото — обложка. Видео пока нет.
4. Настроить показ на витрине, популярное/образ/сезон. Сохранить; обновить витрину. Изменения загружаются из `/api/catalog`, включая варианты и галерею с увеличением.
5. Владелец также создаёт/редактирует поставщиков, контакты, регион, условия, транспорт/импорт, закупочную цену и связь товара с поставщиком. Редактор управляет публичным каталогом и фото, не получает коммерческие поля; сервер игнорирует попытку их изменить редактором.
6. Для снятия товара убрать «Показывать на витрине». Физическое удаление не предусмотрено. При конфликте редактирования из двух окон обновить список и повторно открыть товар: устаревшая версия не перезаписывает новую.

Категории пока фиксированы: женщинам/мужчинам/детям/аксессуары. Произвольное дерево категорий и бренды, переводы/настройки бренда, массовый импорт и редактор видео требуют последующего расширения; критерий текущего этапа — создание/редактирование товара с отражением на витрине. Поставки/закупки и журнал склада относятся к этапу 5.

## Хранение и резервные копии
БД: `data/fashion.sqlite`, SQLite WAL. Данные/хэши пользователей находятся вне публичных маршрутов и исключены из Git. Загруженные фото: `assets/uploads/` (также вне Git). Не удаляйте эти каталоги при обновлении кода.
```
npm run backup -- /абсолютный/путь/backup.sqlite
```
Используется SQLite online backup, а не копирование открытого файла. Держите резервную копию и **весь `assets/uploads/`** вместе, на отдельном носителе с ограниченным доступом. Восстановление: остановить сервер, сохранить текущие данные, восстановить БД в новый путь, указать `FASHION_DB`, восстановить фото, запустить и проверить каталог/вход. Не заменять открытую БД; не смешивать старые файлы `-wal`/`-shm` с восстановленной копией. Тест проверяет чтение резервной БД; автоматическое расписание/внешнее хранилище не подключены.

## Проверки
`npm run check`: синтаксис JS и 8 тестов. Каталог/фильтры/деньги/варианты/лимиты, восстановление локальной корзины, обработчики UI с DOM-заглушкой, SQLite и API (вход/права/CSRF/приватность/создание/изменение/конфликт/повторное открытие/backup). Это не браузерные тесты и не проверка сетевого HTTP-сервера.
Обязательная ручная приёмка после восстановления preview: desktop и 390px, Safari/iPhone, меню и три сегмента, фильтры/пустая выборка, варианты и недоступность, фото/Escape, избранное, корзина/лимиты/удаление/перезагрузка, образ, reduced-motion. Для этапа 3: вход/выход, создание товара/варианта/фото/поставщика, правка и обновление витрины, редактор против владельца, конфликт двух окон, рестарт и восстановление backup.

## Устройство проекта
`index.html`/`style.css` — витрина; `loader.js` — сначала публичный API, затем приложение; `app.js` — рендер и исходный demo seed; `shop-core.js` — правила; `shop.js` — товар/образ/корзина; `admin.html`/`admin.css`/`admin.js` — адаптивная админка; `backend/database.mjs` — схема/валидация/хэши; `backend/application.mjs` — защищённые маршруты и статический allowlist; `backend/seed.mjs` — одноразовая начальная загрузка шести демокарточек; `server.mjs` — HTTP; `manage.mjs` — init/backup/stdin-user; `create-user.mjs` — скрытый интерактивный ввод пароля. Требования и история: SPEC.md, PLANS.md, PROGRESS.md, AGENTS.md.

При HTTP недоступности API витрина сообщает об ошибке, а не подменяет БД зашитыми товарами. Открытие `index.html` как файла поддерживает только старую демонстрацию без БД/админки. Корзина/избранное по-прежнему в localStorage этого браузера, ключи `fashion-demo-v1-*`. Это не серверный заказ, не резерв; персональные данные не запрашиваются.

## До публикации
Получить разрешение владельца. Завершить этапы 4–8 и браузерную приёмку. Заменить демоданные/иллюстрации реальными и проверить права на изображения (ASSETS.md), задать бренд/логотип/контакты/WhatsApp, юридические сведения/условия/политику данных по требованиям Грузии, HTTPS/origin, пользователей/права, мониторинг и расписание резервирования с проверкой восстановления. Сессии ограничены 8 часами, хранятся в памяти и сбрасываются при рестарте. Авторизация использует scrypt, HttpOnly/SameSite cookie, origin-проверку, лимит попыток; до внешнего запуска необходима полноценная проверка среды. Сейчас noindex.
